# QA training — 45 minutes

**Status: NOT DELIVERED.** Outline for TRAIN-03. Use the sandbox project only.

## Learning outcomes

QA can move items from In Testing to Tested to Closed, reopen rejected work,
create well-formed bugs with evidence, filter and report, and explain blocked
transitions.

## Agenda

| Minutes | Topic                           | Demonstration                                           | Practice                     |
| ------: | ------------------------------- | ------------------------------------------------------- | ---------------------------- |
|    0-10 | In Testing to Tested to Closed  | Walk a bug to closure as QA                             | Close one practice bug       |
|   10-18 | Reopening and rejection         | Reopen a closed item with a reason                      | Reopen one item              |
|   18-28 | Creating a good bug             | Steps, expected/actual, severity, attachment            | Create one bug with evidence |
|   28-35 | Filters and saved views         | Filter by state, assignee and priority                  | Save one view                |
|   35-41 | Reports and export              | Run a report and export CSV                             | Verify one count             |
|   41-45 | Blocked transitions and support | Explain developer block at Tested; show `who-to-ask.md` | Questions                    |

## Guardrails

- QA owns the final close transition; do not bypass workflow guards.
- Attach evidence, not screenshots of real customer data.
