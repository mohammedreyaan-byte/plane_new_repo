# Quick reference — Project admins

**Draft for a two-page PDF. Publisher/date: not recorded.**

| Area             | What to manage              | Reminder                                           |
| ---------------- | --------------------------- | -------------------------------------------------- |
| Members          | Invite, change role, remove | Removed members lose access and project email      |
| States/types     | Add and edit                | Keep names understandable for users                |
| Workflows        | Transitions and guards      | Do not remove QA's close control                   |
| Labels           | Create and assign           | Avoid duplicates                                   |
| Cycles           | Plan, close, carry over     | Verify burndown after close                        |
| Modules          | Create and link Epics       | Progress follows children                          |
| Views            | Create and share            | Saved filters are user-visible                     |
| Integrations     | Configure surfaces          | Credentials are operator-supplied; never displayed |
| Service tokens   | Scopes                      | Deny cross-project access by design                |
| Webhooks         | Event mapping               | Wrong events must not post                         |
| Reports/activity | Counts and audit            | Attach evidence for UAT                            |
