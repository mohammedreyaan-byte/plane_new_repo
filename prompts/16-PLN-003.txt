--------------------------------------------------------------------------------
CURRENT STATE AND GAP
--------------------------------------------------------------------------------
Assignee
  - Issue.assignees is a many-to-many through IssueAssignee
    (apps/api/plane/db/models/issue.py).
  - Multiple assignees per work item are supported.
  - The assignee picker lists project members only; workspace admins see all
    workspace members.
  - Filtering supports assignee_id[] and "unassigned".

List layout
  - apps/web/core/components/issues/issue-layouts/list/
  - Grouping by state, priority, assignee, cycle, module, label, created_by,
    and (after PROMPT 06) type.
  - Display properties include ID, assignee, priority, state, start/due date,
    labels, cycle, module, estimate, sub-item count, attachment count, link
    count, created by.
  - Inline editing works for most properties.

Board layout
  - apps/web/core/components/issues/issue-layouts/kanban/
  - Columns by state (or other group-by), card properties configurable.
  - Drag works but does not respect workflows until PROMPT 10.

Actual gaps to close in this prompt:
  1. Assignee options are not filtered by project membership in every entry
     point; a workspace member who is not on the project can be assigned through
     the bulk action and the API.
  2. There is no "Unassigned" quick filter chip, only a filter-menu entry.
  3. List/board preferences are stored per user per view but not per type, so
     switching from Bug to Story keeps Bug-only display choices.
  4. The board shows items whose state is not in the selected type's workflow
     (legacy data) without any warning.
  5. Accessibility: list rows and card move actions are not fully keyboard
     operable; drag announcements are missing.
  6. No bulk assignee change with a per-item result report.

This prompt validates and tightens the layouts. It does not rebuild the layouts.

--------------------------------------------------------------------------------
WORK ITEM 1 - ASSIGNEE CORRECTNESS
--------------------------------------------------------------------------------
Backend (apps/api/plane/app/serializers/issue.py, views/issue/*, views/project.py):
  - Validate every assignee id: must be a ProjectMember of the target project
    (workspace admins may be assigned only if they are added to the project; do
    not implicitly add them).
  - Reject unknown, inactive, or cross-workspace users -> 400
    invalid_assignee with the offending ids.
  - Bulk assignment returns {updated, skipped, failed, results[]} with a reason
    per item; atomic mode aborts on the first failure.
  - Creating an item with assignees not on the project fails; do not silently
    drop them.
  - Assignment emits the notification event from PROMPT 14 and a webhook
    payload including assignee_ids.

Frontend:
  - The picker queries project members, not workspace members, for members;
    workspace admins with project access appear only if they are project
    members.
  - Show avatar, name, email on hover; search by name and email.
  - Add an "Unassigned" chip and an "Assigned to me" chip to the issue header
    filter row (single click, visible state).
  - Bulk assign dialog with a preview of affected items and the per-item result
    after submit.
  - Assignment is capability-gated (work_item.assign) and disabled with a
    tooltip for Viewer/Guest.

--------------------------------------------------------------------------------
WORK ITEM 2 - LIST LAYOUT VALIDATION
--------------------------------------------------------------------------------
  - Verify grouping and sub-grouping for every supported key, including type.
  - Column visibility: display properties persist per user, per layout and per
    type. Store in the existing user preference mechanism, not a new table.
  - Inline edit: every editable cell has an accessible label, keyboard entry,
    escape to cancel, enter to save, and a visible error on failure.
  - Sticky header and first column; horizontal scroll does not hide the
    identifier.
  - Row selection with shift-click range, select-all-on-page (not all results),
    and a clear selection action.
  - Empty groups render a dashed add row, not a blank area.
  - Mobile: collapse to a card list with the same properties and actions.
  - Performance: 50 rows must not trigger more than the baseline queries; no
    per-row assignee or type fetch (use hydrated stores).

--------------------------------------------------------------------------------
WORK ITEM 3 - BOARD LAYOUT VALIDATION
--------------------------------------------------------------------------------
  - Columns respect Group by. If grouped by assignee, columns are project
    members plus Unassigned.
  - Card display properties match the list preferences but are stored
    separately.
  - Card menu and drag handle are reachable by keyboard; a full keyboard move is
    available via "Move to" menu.
  - Column collapse state persists per user per view.
  - Column header shows count; WIP limit from PROMPT 10 when enabled.
  - Unmapped-state warning: if an item's state is not part of the selected
    type's workflow, show a badge "Unmapped state" on the card and a banner
    above the board. Do not hide the card.
  - Empty column: dashed drop zone and an add button that preselects the state.
  - Do not allow dragging a card into an invalid column (PROMPT 10 owns the
    rule; this prompt verifies the layout handles the blocked state visually).

--------------------------------------------------------------------------------
WORK ITEM 4 - SAVED PREFERENCES
--------------------------------------------------------------------------------
  - Store per-user preferences for: layout, group by, sub-group by, order by,
    display properties, column widths, collapsed columns, per-type overrides.
  - Use the existing user/project preference endpoints; add fields only when a
    suitable one does not exist.
  - Preferences must survive reload, logout/login and a different browser.
  - A View stores the shared configuration (PROMPT 17); personal preferences
    never overwrite the shared view for other users.

TESTS
