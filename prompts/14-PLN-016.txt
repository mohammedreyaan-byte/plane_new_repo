DATA MODEL
--------------------------------------------------------------------------------
1. Extend UserNotificationPreference:
     assignment = BooleanField(default=True)
     due_date = BooleanField(default=True)
     digest_frequency = CharField(20, default="instant",
                                  choices instant|daily|off)
     email_enabled = BooleanField(default=True)

2. Extend EmailNotificationLog (or add EmailDeliveryLog if the existing table is
   unsuitable; prefer extending to avoid two logs):
     status CharField(20)          # queued, sent, failed, bounced, skipped
     attempts PositiveInteger
     provider_message_id CharField(255)
     error TextField
     event_key CharField(50)
     recipient_email EmailField
     template CharField(100)
     sent_at DateTime(null=True)
   Retention 90 days; purge task.

3. UnsubscribeToken model or signed token:
     user, event_key, created_at, used_at
   One-click unsubscribe per event type; signed with SECRET_KEY; no login
   required; GET shows a confirmation page, POST performs it. Never unsubscribe
   security emails (password reset, invitation).

--------------------------------------------------------------------------------
EVENT AND RECIPIENT RULES
--------------------------------------------------------------------------------
  Event            Recipients                                   Preference
  assigned         added assignees, excluding actor            assignment
  unassigned       removed assignees, excluding actor           assignment
  state_changed    assignees, subscribers, creator, lead        state_change
  commented        subscribers, assignees, mentioned, creator   comment
  mentioned        mentioned users only                         mention
  completed        assignees, subscribers, creator, lead        issue_completed
  due_soon         assignees, project lead                      due_date
  overdue          assignees, project lead                      due_date

Rules:
  - Never notify the actor about their own action, unless self-mention.
  - Deduplicate (event_key, entity_id, recipient_id, actor_id) within 5 minutes.
  - Respect workspace/project membership and project isolation: never email a
    user who cannot access the project.
  - Honour email_enabled, the per-event toggle and digest_frequency.
  - Guest recipients follow the guest visibility rule (own items only).
  - Use the project time zone for due dates.
  - Batch daily digests at 08:00 in the user's time zone; include unread events
    only.
  - Do not send events older than 24 hours (avoids a backlog storm after an
    outage).
  - Plain-text alternative for every email.

IMPLEMENTATION
--------------------------------------------------------------------------------
- Assignment detection: diff IssueAssignee before/after in the update service
  (apps/api/plane/app/views/issue/base.py) and emit assigned/unassigned events.
- Extend the existing activity/notification dispatcher rather than creating a
  parallel one. Map activity types to event keys.
- Queue email through Celery (apps/api/plane/bgtasks/). Never send synchronously
  in a request.
- Use EmailMultiAlternatives with HTML + text templates.
- Templates: apps/api/templates/emails/ (existing: auth, invitations,
  notifications, user) with the existing base.html branded layout:
  workspace name, event summary, actor, work item link, footer, unsubscribe.
- Retry soft failures 3x with backoff; hard bounce -> mark and stop retrying.
- EMAIL_TEST_MODE=true redirects all mail to a configured test address.
- Due-date task: daily scan for items due in 2 days and overdue; one email per
  item per user per day.
- Admin delivery log and bounce list.
- Existing SMTP settings: use them; do not add a second SMTP config.
