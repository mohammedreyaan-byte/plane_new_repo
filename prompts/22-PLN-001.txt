CONTEXT
--------------------------------------------------------------------------------
The running instance uses stock makeplane images (v1.4.2). There is no internal
fork, no branch policy and no CI. Every later prompt assumes a fork where a pull
request is built, tested and reviewed before merge.

Local checkout:
  C:\Users\DELL\Desktop\Projects\Plane Project\plane
  currently on branch sdlc-work at tag v1.4.2 (matches the deployed images).

--------------------------------------------------------------------------------
OBJECTIVE
--------------------------------------------------------------------------------
Create the internal fork of Plane CE, pin it to the deployed version, document
the engineering standards, and make CI build and test both the API and the web
app on every pull request.

--------------------------------------------------------------------------------
STEPS
--------------------------------------------------------------------------------
1. Fork and pin
   - Fork https://github.com/makeplane/plane into the internal GitHub org.
   - Keep the upstream remote:
       git remote add upstream https://github.com/makeplane/plane.git
   - Create long-lived branches:
       main        tracks the internal, deployable code
       upstream    mirrors makeplane/plane at the pinned tag
   - Tag the starting point:
       git tag baseline-v1.4.2 v1.4.2
       git push origin main baseline-v1.4.2
   - Record in README-INTERNAL.md: CE is AGPL-3.0, the pinned upstream tag, and
     the rule that Commercial/Pro code is never copied.

2. Standards
   - Add CONTRIBUTING-INTERNAL.md containing:
       * Branch names: feature/PLN-xxx-short-name, fix/PLN-xxx-short-name,
         chore/PLN-xxx-short-name.
       * Conventional Commits, examples and scopes (types, workflow, roles,
         github, slack, tokens, reports, backlog, board, modules, notify).
       * Definition of Done: code, tests, migration check, docs, screenshot or
         curl evidence, no placeholders.
       * Review rules: one approving reviewer, no self-merge, CI green,
         migrations reviewed by a second engineer.
       * AGPL header rule for new files.
   - Add .editorconfig and keep the repo's existing formatters/linters
     (oxlint/oxfmt/prettier for web, ruff/black for API). Do not introduce a
     second formatter.

3. CI workflows under .github/workflows/
   Create these jobs. Cache dependencies; fail fast; upload artifacts.

   ci-api.yml
     - services: postgres:15.7, valkey/valkey:7.2
     - python 3.11 (match apps/api/Dockerfile)
     - pip install -r requirements.txt (or the repo's uv/poetry path)
     - python manage.py makemigrations --check --dry-run
     - python manage.py migrate
     - pytest (or the repo's test runner) with coverage
     - ruff check and format check

   ci-web.yml
     - node 24, corepack enable pnpm
     - pnpm install --frozen-lockfile
     - pnpm --filter web lint
     - pnpm --filter web typecheck (or tsc --noEmit)
     - pnpm --filter web test
     - pnpm --filter web build

   ci-images.yml (on main and tags)
     - docker buildx build for apps/api and apps/web using the repo Dockerfiles
     - push to the internal registry with the commit SHA tag
     - run a Trivy scan; fail on HIGH/CRITICAL with a fix available

   ci-migrations.yml
     - apply migrations to a dump of the SDLC database restored into a
       disposable postgres service
     - run the data backfills twice to prove idempotency
     - run the integrity checks from Requirements.docx section 18.6

   licence-check.yml
     - assert LICENSE.txt is present and unmodified
     - grep new source files for the AGPL header
     - fail if files mention "plane-pro", "commercial", or import a private
       package

4. Branch protection on main
   - Require PR, 1 approval, CI green, branch up to date, conversation resolved.
   - Disallow force push and deletion.
   - Require signed commits if the org already does.

5. Local developer bootstrap
   - Document `corepack enable pnpm`, Node 24, Python 3.11, Docker Desktop.
   - Document how to run the stack from source:
       docker compose -f docker-compose-local.yml up --build
     or the repo's documented dev compose. Provide the exact commands that work
     on Windows PowerShell.
   - Document how to point the local web app at the local API.
