DATA MODEL (extend APIToken, additive)
--------------------------------------------------------------------------------
  token_prefix      CharField(12)      # plane_api_ab12 (first 8 chars)
  token_hash        CharField(64)      # sha256 hex, indexed
  project_ids       JSONField(default=list)  # [] = all projects in workspace
  capabilities      JSONField(default=list)
  revoked_at        DateTime(null=True)
  created_by        FK User(null=True, on_delete=SET_NULL, related_name="+")
  last_used         DateTime(null=True)
  allowed_rate_limit CharField(255, default="60/min")

Keep `token` for legacy lookup during migration. New tokens still write a
plaintext value only until the compatibility window closes; then a migration
clears it and the lookup uses token_hash.

Capabilities:
  work_item.read, work_item.create, work_item.edit, work_item.transition,
  comment.read, comment.create, link.read, link.create, attachment.read,
  report.read

Never grant: member.manage, project.manage, type.manage, workflow.manage,
integration.manage, service_token.manage.

Bot user:
  - Each service token has a bot user (user_type=1) with project membership and
    the minimum role (Developer or QA) needed for its transitions.
  - Document: if the token must perform QA-only transitions, the bot user gets
    the QA role. Service tokens do not bypass role rules.

AUTHENTICATION
--------------------------------------------------------------------------------
Find the API key authentication class (grep for X-Api-Key / APIKeyAuthentication
under apps/api/plane/api and apps/api/plane/authentication).

Changes:
  - Look up by token_hash first; if not found, look up by token, then compute
    and store the hash (lazy migration).
  - Reject revoked_at, expired_at < now, inactive user, inactive workspace
    membership.
  - Enforce workspace match.
  - Enforce project scope after authentication:
      extract project_id from the URL; if project_ids is non-empty and the
      project is not in it -> 403 {"code": "project_scope_denied"}.
      Do this in a permission/middleware layer, not only in each view.
  - Enforce capabilities per endpoint via PROMPT 01's service.
  - Update last_used at most once per minute.
  - Log every request to APIActivityLog: method, path, status, ip, user agent,
    token prefix. Never log the token.

URL/header rules:
  - Header only: X-Api-Key. Reject tokens in query strings.
  - Redact query strings in logs.

--------------------------------------------------------------------------------
API
--------------------------------------------------------------------------------
  GET    /api/workspaces/<slug>/service-tokens/
  POST   /api/workspaces/<slug>/service-tokens/
  GET    /api/workspaces/<slug>/service-tokens/<id>/
  PATCH  /api/workspaces/<slug>/service-tokens/<id>/
  DELETE /api/workspaces/<slug>/service-tokens/<id>/     revoke immediately
  POST   /api/workspaces/<slug>/service-tokens/<id>/rotate/
  GET    /api/workspaces/<slug>/service-tokens/<id>/usage/

Create request:
  {
    "label": "GitHub Actions - SDLC",
    "description": "Updates work items from CI",
    "project_ids": ["uuid"],
    "capabilities": ["work_item.read","work_item.edit","comment.create",
                     "link.create"],
    "expires_at": "2027-11-04T00:00:00Z",
    "allowed_rate_limit": "120/min"
  }

Response (only once):
  { "id", "label", "token", "token_prefix", "created_at", "expires_at",
    "project_ids", "capabilities" }

All later reads omit `token` and return token_prefix only.
Rotate: create a replacement, set the old revoked_at after a grace period
(default 24h), return the new token once.
Revoke: immediate; the next request fails with 401.

Permissions: workspace admin only (service_token.manage).
