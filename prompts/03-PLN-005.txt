CONTEXT AND VERIFIED CODE FACTS
--------------------------------------------------------------------------------
- States are project-wide: apps/api/plane/db/models/state.py:79.
  State has name, group, sequence, default, is_triage. There is no type
  association and no transition table anywhere in the backend.
- apps/api/plane/app/views/issue/base.py updates state_id directly. Any state in
  the project is accepted.
- The board (apps/web/core/components/issues/issue-layouts/kanban) renders the
  project state list and allows dropping a card into any column.
- Project Settings -> Automations only has auto-archive and auto-close; it is
  not a workflow engine.

Build the engine once, in the backend, and make every state-changing path use it.
Do not put transition rules in React.

DATA MODEL (new file apps/api/plane/db/models/workflow.py)
--------------------------------------------------------------------------------
class Workflow(ProjectBaseModel):
    name         CharField(120)
    description  TextField(blank=True)
    issue_type   FK("db.IssueType", null=True, blank=True,
                    on_delete=CASCADE, related_name="workflows")
    is_default   BooleanField(default=False)
    is_active    BooleanField(default=True)
    # unique active default per (project, issue_type)

class WorkflowState(ProjectBaseModel):
    workflow  FK(Workflow, related_name="workflow_states")
    state     FK("db.State", related_name="workflow_states")
    sequence  FloatField(default=65535)
    is_initial BooleanField(default=False)
    is_final   BooleanField(default=False)
    # unique (workflow, state) where deleted_at is null
    # exactly one is_initial per workflow (validated in service + constraint check)

class WorkflowTransition(ProjectBaseModel):
    workflow          FK(Workflow, related_name="transitions")
    from_state        FK("db.State", related_name="transitions_from")
    to_state          FK("db.State", related_name="transitions_to")
    allowed_roles     JSONField(default=list)   # role keys; [] = any contributor
    requires_comment  BooleanField(default=False)
    required_fields   JSONField(default=list)   # e.g. ["assignee","estimate"]
    admin_override    BooleanField(default=True)
    is_active         BooleanField(default=True)
    # unique (workflow, from_state, to_state) where deleted_at is null

Notes:
  - Reuse the existing State rows; do not duplicate states per type. The mapping
    table is what makes states type-specific. This avoids breaking cycles,
    analytics and existing state filters.
  - Later, if a team needs the same state name with different settings per type,
    they create a second State row with a different name; the engine supports it.
  - Export all three models from apps/api/plane/db/models/__init__.py.

Migrations:

  seed_bug_workflow (data, idempotent)
  backfill_workflows_for_existing_projects (data)

BUG WORKFLOW SEED
--------------------------------------------------------------------------------
States (create if a state with the same name does not exist in the project;
reuse if it does):

  name          group        sequence  initial  final
  New           unstarted    15000     yes      no
  In Progress   started      25000     no       no
  Code Review   started      35000     no       no
  In Testing    started      45000     no       no
  Tested        started      55000     no       no
  Closed        completed    65000     no       yes
  Reopened      unstarted    75000     no       no
  Rejected      cancelled    85000     no       yes

Transition matrix (from -> to, allowed roles):
  New          -> In Progress    [] (any contributor)
  New          -> Rejected       ["admin","member"]
  In Progress  -> Code Review    []
  In Progress  -> In Testing     []
  In Progress  -> Rejected       ["admin","member"]
  Code Review  -> In Progress    []
  Code Review  -> In Testing     []
  In Testing   -> Tested         ["qa","admin"]
  In Testing   -> In Progress    []
  Tested       -> Closed         ["qa","admin"]
  Tested       -> Reopened       ["qa","admin","member"]
  Tested       -> In Testing     ["qa","admin"]
  Closed       -> Reopened       ["qa","admin"]
  Reopened     -> In Progress    []
  Reopened     -> Rejected       ["admin","member"]

Every state is reachable from at least one transition. Closed and Rejected are
final but may be reopened (the transition exists; is_final is informational for
UI and reporting).

Idempotency: match workflows by (project, issue_type, name); match states by
(project, name); match transitions by (workflow, from, to). Re-running the seed
must not duplicate rows.

TRANSITION SERVICE
--------------------------------------------------------------------------------
Create apps/api/plane/utils/workflow/__init__.py and transition.py.

  get_workflow_for_issue(issue) -> Workflow | None
      type-specific default workflow, else project default workflow
  get_allowed_transitions(issue, user) -> list[Transition]
      active transitions from issue.state; filtered by role capability
  validate_transition(issue, to_state, user, payload) -> Transition
      raises WorkflowError with a machine code
  transition_issue(issue, to_state_id, user, *, comment=None,
                   fields=None, source="api") -> Issue
      - lock the issue row (select_for_update) inside a transaction
      - load workflow; if none, fail closed only when the project has workflows
      - validate from->to
      - validate required comment and required fields
      - validate role (delegate to PROMPT 05 when present; until then read
        allowed_roles directly)
      - update state_id, completed_at when entering a completed group,
        clear completed_at when leaving it
      - create IssueActivity (field=state, old_value, new_value, actor)
      - enqueue notifications and webhooks after commit
      - return the issue

Error codes (HTTP 400/403/409, plus 503 when the workflow is unavailable):
  workflow_not_found        503 (state changes blocked, other edits allowed)
  state_not_in_workflow     400
  transition_not_allowed    400
  transition_forbidden      403 (role denial; include required_roles)
  comment_required          400
  fields_required           400 (include missing field names)
  stale_workflow            409 (transition deleted/changed during the move)
  invalid_state             400

Enforcement points - every one must call transition_issue:
  apps/api/plane/app/views/issue/base.py partial_update/create-with-state
  apps/api/plane/api/views/issue.py update (and any new transition action)
  bulk update flow: today the web app sends one PATCH per item
    (apps/web/core/store/issue/*), so each PATCH already hits the service.
    If you add a server-side bulk endpoint, call transition_issue per item and
    return per-item results. Do not create a bypass just for bulk.
  apps/api/plane/app/views/issue/archive.py          archive/unarchive only;
    touch state only if it currently mutates state (verify before editing)
  apps/api/plane/app/views/intake/base.py (accept) - set initial state, no
    transition (intake accepts into a state; treat it as creation, not a move)
  apps/api/plane/app/views/cycle/issue.py transfer-issues - preserve state
    unless the target cycle sets a start state; then use transition_issue
  CE v1.4.2 has serializers/importer.py but no importer view/URL. If an importer
    is added later, it must use source=import and record imported=true. Do not
    invent an importer for this prompt.
  future automation - system actor with explicit capability

Guard against bypass:
  - Add a Django system check or CI grep that fails if `issue.state =` or
    `Issue.objects.filter(...).update(state=` appears outside the allowlist
    (transition service, migrations, tests).
  - Document the allowlist in apps/api/plane/utils/workflow/README.md.

API
--------------------------------------------------------------------------------
  GET  /api/workspaces/<slug>/projects/<pid>/workflows/
  POST /api/workspaces/<slug>/projects/<pid>/workflows/
  GET/PATCH/DELETE .../workflows/<workflow_id>/
  PUT  .../workflows/<workflow_id>/states/          ordered list of state ids
  GET/POST .../workflows/<workflow_id>/transitions/
  PATCH/DELETE .../workflows/<workflow_id>/transitions/<transition_id>/
  POST .../workflows/<workflow_id>/clone/           {"name": "...", "issue_type_id": "..."}
  POST .../workflows/<workflow_id>/reset/           restore the default matrix
  GET  .../workflows/health/                        validation report
  GET  .../workflows/<workflow_id>/allowed-transitions/?issue_id=...
  POST .../work-items/<issue_id>/transition/        {"to_state_id": "...", "comment": "..."}

Serializers:
  apps/api/plane/app/serializers/workflow.py
    WorkflowSerializer: id, name, description, issue_type, issue_type_detail,
      is_default, is_active, states (ordered), transitions_count, health
    WorkflowStateSerializer: id, state_id, state_detail, sequence, is_initial,
      is_final
    WorkflowTransitionSerializer: id, from_state_id, to_state_id, allowed_roles,
      requires_comment, required_fields, admin_override, is_active
  apps/api/plane/api/serializers/workflow.py mirrors read-only for v1.

Validation:
  - Workflow type must be enabled in the project.
  - States must belong to the project.
  - Exactly one initial state.
  - No duplicate from/to.
  - No self-transition.
  - At least one final state.
  - Return 400 with per-field errors.
  - Health endpoint returns: missing_initial, missing_final, unreachable_states,
    duplicate_default, items_in_unmapped_states.

Permissions: read = project member; write = project admin or workspace admin
(capability workflow.manage). Use PROMPT 01's service.
