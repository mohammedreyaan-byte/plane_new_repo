DATA MODEL
--------------------------------------------------------------------------------
1. Extend IssueType (new migration, additive only):
     key = SlugField(max_length=50, null=True)   # bug, task, story, epic
     is_epic already exists - keep it
     is_default already exists - keep it
     is_active already exists - keep it
   Add constraint: unique (workspace, key) where deleted_at is null and key is
   not null.
   Backfill key from slugify(name) for any existing row (currently zero rows,
   but the migration must be safe).

2. Extend ProjectIssueType:
     is_enabled = BooleanField(default=True)
     is_default = BooleanField(default=False)     # already exists, keep
     level already exists, use it for ordering
   Constraint: at most one is_default=true per project where deleted_at is null
   (partial unique index). At most one workspace-level default type
   (IssueType.is_default=true and workspace=... ) is allowed.

3. Seed data migration per workspace (idempotent):
     Bug    key=bug    is_epic=false  icon/colour bug     level 0  default
     Task   key=task   is_epic=false  icon/colour task    level 1
     Story  key=story  is_epic=false  icon/colour story   level 2
     Epic   key=epic   is_epic=true   icon/colour epic    level 3
   For every existing project create ProjectIssueType rows for all four,
   is_enabled=true, and Task is_default=true.
   For every project with is_issue_type_enabled=true, enable the four types.
   Do not flip the flag for existing projects in this migration; enable it for
   SDLC in a separate, explicit data step after UAT.

4. Backfill issues:
   - For every issue with type_id null, set the project's default type
     (Task) in batches of 500 using iterator().
   - For issues carrying the label whose name is `type: bug` (case-insensitive),
     set type=Bug, then remove the label link. Do this only when the project has
     types enabled. Log counts.
   - Never touch issues in projects with types disabled.
   - The migration must be re-runnable and report {scanned, updated, skipped}.

5. Add `type` to indexes and select_related in list queries (see PROMPT 06).

  Create payload:
    { "name": "Bug", "key": "bug", "description": "...",
      "logo_props": {"icon": "bug", "color": "#..."},
      "is_epic": false, "is_default": false, "level": 0 }
  Response includes id, key, name, description, logo_props, is_epic,
  is_default, is_active, projects_count.

Project enablement:
  GET    /api/workspaces/<slug>/projects/<pid>/work-item-types/
  POST   /api/workspaces/<slug>/projects/<pid>/work-item-types/
         body {"issue_type_id": "...", "is_enabled": true, "is_default": false}
  PATCH  /api/workspaces/<slug>/projects/<pid>/work-item-types/<id>/
  DELETE /api/workspaces/<slug>/projects/<pid>/work-item-types/<id>/
  POST   /api/workspaces/<slug>/projects/<pid>/work-item-types/reorder/

Validation rules:
  - Type must belong to the same workspace. Cross-workspace -> 400.
  - Deleting a type with issues -> 409 with count; require ?force=true and then
    reassign to the project default in a transaction.
  - Deleting the default type -> 409 default_type_protected.
  - Deleting the epic type while modules link to it -> 409 epic_type_in_use.
  - Enabling a type is idempotent.
  - Setting is_default=true atomically clears the previous default.
  - Project with is_issue_type_enabled=false: GET returns the four types with
    is_enabled=false; mutations return 400 types_disabled.

Issue payload changes (additive, both surfaces):
  - Read: `type_id` (uuid or null) and `type` object
      {id, key, name, logo_props, is_epic}
  - Write: `type_id` accepted on create and PATCH.
  - Create without type_id -> project default (already implemented in v1;
    replicate in the web serializer/view path).
  - PATCH type_id to a type not enabled in the project -> 400.
  - Changing type when the item's state is not in the new type's workflow:
    allowed only after PROMPT 03 exists; until then, do not change state.
    When workflows exist, reset to the new workflow's initial state and record
    an activity row "Type changed from X to Y; state reset to Z".
  - Bulk update accepts type_id.
  - Webhook payloads include type_id, type_key, type_name.

Implement in:
  apps/api/plane/app/serializers/issue.py        (read + write, list projection)
  apps/api/plane/app/views/issue/base.py         (create/update)
  apps/api/plane/api/serializers/issue.py        (keep and align)
  apps/api/plane/api/views/issue.py
  apps/api/plane/app/serializers/project.py      (expose is_issue_type_enabled)
  apps/api/plane/app/serializers/state.py        (later: type-aware states)
