--------------------------------------------------------------------------------
WORK ITEM 1 - METRIC DEFINITIONS (single source of truth)
--------------------------------------------------------------------------------
Create apps/api/plane/utils/analytics/metrics.py and use it for both analytics
and reports (PROMPT 12):

  open          state.group in (backlog, unstarted, started)
                and archived_at is null and deleted_at is null and not draft
  resolved      state.group == completed
  cancelled     state.group == cancelled
  created       created_at in range
  resolved_at   completed_at in range
  reopened      state.group != completed and completed_at was set before; use
                activity history, do not guess

Time bucket: day/week/month in the project or cycle timezone; the timezone is
returned in meta so the UI can display it.

Every chart must state its definition in a tooltip or info icon. If two charts
disagree, that is a bug in this prompt.

--------------------------------------------------------------------------------
WORK ITEM 2 - TYPE DIMENSION
--------------------------------------------------------------------------------
  - Add type_id/type_id__in filters to every analytics endpoint.
  - Add group_by=type_id and a type dimension in the response.
  - Summary tiles: total open, open bugs, resolved this period, overdue, by
    type breakdown (additive).
  - Type filter persists in the URL and in saved analytics views.
  - If types are disabled for the project, hide the selector and fall back to
    the legacy label-based definition, with a visible note.
  - Query set must select_related("type") and not N+1.

--------------------------------------------------------------------------------
WORK ITEM 3 - CORRECTNESS FIXES
--------------------------------------------------------------------------------
Audit each existing chart against the definitions and fix mismatches:
  - Archived items must be excluded from "open" but included in an explicit
    "archived" bucket when the chart shows totals.
  - Cancelled items must not count as resolved in trend lines.
  - Reopened items must leave "resolved" on the date of reopening.
  - Cycle progress must use the cycle's items, not a date-range approximation.
  - Module progress must share the helper in PROMPT 11.
  - Assignee breakdown: unassigned is a bucket; deleted users show "Former
    member" and are not dropped from historical data.
  - Priority ordering in charts is urgent..none, not alphabetical.
  - Percentages always sum to 100 or show "other"; never round to 101.

Add assertions in tests that compare each chart's total with a direct SQL count
for a fixed fixture.

--------------------------------------------------------------------------------
WORK ITEM 4 - UI AND EXPORT
--------------------------------------------------------------------------------
  - Header: date range (presets 7/30/90 days, this cycle, this quarter, custom,
    max 2 years), type selector, project selector when the page is workspace
    scope, refresh.
  - Tiles: open, resolved, created, cancelled, overdue, avg time to resolve.
  - Charts: trends, state breakdown, priority, assignee, type, cycle, module.
  - Every chart has a table equivalent (toggle) and a text summary for screen
    readers.
  - Empty state: "No data for this range" with clear filters.
  - Loading: skeletons that preserve layout; do not flash empty charts.
  - Error: retry without losing filters.
  - Export: CSV and PNG per chart, plus "Export all" for a saved analytics
    view; CSV matches the table, escapes formulas, includes filters and
    timezone in a header block.
  - Saved analytics views: name, filters (including type), charts, public or
    private, owner. Reuse the View permission model from PROMPT 17.
  - Mobile: tiles stack, charts scroll, table view is the default below 768px.

Navigation: analytics already exists in the workspace/project navigation. Do
not add a second entry; the Reports page from PROMPT 12 links to it and vice
versa.

--------------------------------------------------------------------------------
API (additive)
--------------------------------------------------------------------------------
  GET /api/workspaces/<slug>/projects/<pid>/analytics/?type=work-items&type_id=...
  GET .../analytics/?type=work-items&group_by=type_id
  GET .../analytics/export/?chart=...&format=csv|png&filters...
  GET .../analytics/views/  (workspace/project saved views)
  POST/PATCH/DELETE .../analytics/views/<id>/

Return meta with {timezone, date_from, date_to, filters, definitions_version}
so a saved chart can be reproduced exactly.
