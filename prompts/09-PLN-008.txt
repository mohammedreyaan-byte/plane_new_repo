CURRENT STATE AND GAP
--------------------------------------------------------------------------------
"Backlog" exists only as a state group (StateGroup.BACKLOG). There is no Backlog
route, no dedicated ordering, and no bulk move. Moving an item into a Cycle is a
single-item property edit through the cycle-issues endpoint.

Existing pieces to reuse:
  - Cycles: apps/api/plane/db/models/cycle.py, CycleIssue model
  - Transfer: POST .../cycles/<cycle_id>/transfer-issues/ (carry-over)
  - sort_order on Issue for board column ordering (do not reuse for backlog)
  - Project navigation: apps/web/core/components/navigation/use-navigation-items.ts

--------------------------------------------------------------------------------
DATA MODEL
--------------------------------------------------------------------------------
1. Issue.backlog_rank = CharField(max_length=64, null=True, blank=True)
   Index (project, backlog_rank). Use fractional indexing with lexicographic
   keys (a0, a0V, a1) so insertion never renumbers the list.

2. Project.backlog_enabled = BooleanField(default=True)
   Expose as `backlog_enabled` in the project serializer.
   When false, the route and nav item are hidden and the API returns 404.

3. Cycle.capacity_points = PositiveIntegerField(null=True)
   Cycle.is_capacity_hard_limit = BooleanField(default=False)
   Project.backlog_new_item_position = CharField(10, choices top|bottom,
   default bottom).

4. No extra timestamp column. Ordering uses backlog_rank only. "Time in
   backlog" reporting is out of scope for this prompt and must not be derived
   from updated_at.

Migrations: one schema migration per model change; one data migration to assign
initial ranks to existing backlog-group items (ordered by created_at, sequence).

Rank helper: apps/api/plane/utils/rank.py
  generate_rank_between(prev, next) -> str
  generate_rank_first() / generate_rank_last()
  rebalance(project) when a key exceeds 64 chars or the gap is exhausted.
Use a proven fractional-indexing algorithm; unit-test the edge cases.

--------------------------------------------------------------------------------
BACKEND API
--------------------------------------------------------------------------------
GET /api/workspaces/<slug>/projects/<pid>/backlog/
  - Items whose state.group == backlog, not archived, not deleted, not draft
    (unless include_drafts=true and the user is an admin).
  - Order by backlog_rank asc, then sequence_id asc.
  - Include type, priority, assignee(s), estimate, cycle, module, labels, state.
  - Filters: type_id, priority, assignee_id, label_id, cycle_id (including
    "none"), module_id, search.
  - Cursor pagination on backlog_rank (stable infinite scroll).
  - Response meta: total, total_estimate, project_id, next_cursor.

PATCH /api/workspaces/<slug>/projects/<pid>/backlog/reorder/
  body: {"issue_id": "...", "before_id": "...", "after_id": "..."}
  - Validate all IDs belong to the project and are in a backlog state.
  - Compute rank between neighbours in one transaction.
  - select_for_update on the neighbours or optimistic updated_at check; 409 on
    conflict with the current neighbours so the client refetches.
  - If the gap is exhausted, rebalance the affected page in the same transaction.
  - Return {issue_id, backlog_rank}.

POST /api/workspaces/<slug>/projects/<pid>/backlog/reorder/bulk/
  body: {"issue_ids": ["..."]} in the desired order (max 200).
  - Assign sequential ranks inside the gap; one transaction; idempotent.

POST /api/workspaces/<slug>/projects/<pid>/backlog/bulk-move-to-cycle/
  body: {
    "issue_ids": ["..."],
    "cycle_id": "...",
    "remove_from_backlog": true,
    "atomic": false
  }
  - Validate: cycle belongs to the project and is not completed; items belong to
    the project, are not archived/deleted; no duplicate ids.
  - Create CycleIssue rows idempotently. If an item is already in another cycle,
    move it by default or skip when "move_existing": false.
  - If remove_from_backlog, transition each item to the cycle's start state
    (default Todo) through transition_issue (PROMPT 03); preserve type.
  - Capacity: sum estimates + current cycle points. Over capacity -> warn; if
    is_capacity_hard_limit -> 409 with overflow details and per-item results.
  - Return {moved, skipped, failed, results[], capacity_after}.
  - Emit cycle_issue webhooks and activity rows.
  - atomic=true: all or nothing. atomic=false: per-item result.

Permissions:
  - Read: work_item.view.
  - Reorder/bulk move: work_item.edit; cycle assignment also requires
    cycle.manage or project Member/Admin per the capability matrix.

Backlog rank on create:
  - New item in a backlog state gets a rank at top/bottom per project setting.
  - Items moved out keep their rank for restoration; items moved in with null
    rank get one at the bottom.
  - Type change preserves rank.
