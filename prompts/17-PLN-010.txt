--------------------------------------------------------------------------------
PERMISSION MODEL
--------------------------------------------------------------------------------
  Access 0 (Private): only the owner can read, edit, delete, duplicate.
  Access 1 (Public):
    read      any project member with work_item.view
    edit      owner, project admin, or workspace admin
    delete    owner, project admin, or workspace admin
    lock      project admin only (is_locked stops edits but not reads)
  Guest: can read a public view only if it resolves to items they can see; the
    view responds with the intersection, never with a 403 that reveals counts.
  Workspace views follow the same rule at workspace scope; admin can restrict a
    workspace view to selected projects.

Enforce in apps/api/plane/app/views/view/base.py (and the workspace-view view).
Never rely on the UI to hide the edit button.

BACKEND WORK
--------------------------------------------------------------------------------
1. Extend IssueView with additive fields only:
     last_updated_by FK User null
     last_updated_at auto
     is_default Boolean default false      (one per project per workspace scope)
     project_ids JSONField default list    (workspace views only; [] = all)
     schema_version PositiveSmallInteger default 1
   Migration: add_view_sharing_fields, data migration sets last_updated_by =
   owned_by, schema_version = 1.

2. Validation and behaviour:
   - is_default true clears the previous default in the same scope atomically.
   - Deleting the default view promotes the oldest public view or none; never
     leave a dangling default.
   - is_locked blocks PATCH of query/filters/display_* but permits renaming and
     re-sharing by an admin.
   - Duplicate copies filters, display properties, access (private copy unless
     the caller is an admin) and appends " (copy)".
   - Archived views are excluded from lists; restore clears archived_at.
   - Reject unknown filter keys only if the existing serializer already does;
     otherwise persist and validate at read time.
   - Return `filter_health` on GET: [{key, value, status: ok|unknown|deleted,
     label}] so the UI can explain an empty list.

3. Workspace view project scoping:
   - GET accepts project_ids and validates membership.
   - The query builder adds an `in project_id` clause when project_ids is not
     empty, regardless of any other filter (defence in depth).
   - A user who is not a member of a selected project sees that project's items
     filtered out, not a 403.

4. API (keep existing paths, add only what is missing):
     GET/POST      /api/workspaces/<slug>/projects/<pid>/views/
     GET/PATCH/DELETE /api/workspaces/<slug>/projects/<pid>/views/<view_id>/
     POST          .../views/<view_id>/duplicate/
     POST          .../views/<view_id>/lock/     {"is_locked": true}
     POST          .../views/<view_id>/archive/
     POST          .../views/<view_id>/restore/
     GET/POST      /api/workspaces/<slug>/views/            workspace views
     GET/PATCH/DELETE /api/workspaces/<slug>/views/<view_id>/

5. Seed command (idempotent), extending PROMPT 06's command:
     python manage.py seed_standard_views --workspace workspace-test
   Project views for SDLC (is_public unless stated):
     My open bugs            type Bug, state group unstarted+started,
                             assignee dynamic current user
     Ready for testing       type Bug, state In Testing
     Reopened                type Bug, state Reopened
     Current sprint          current active cycle, all types
     Unassigned high priority priority urgent+high, assignee none
     Recently completed      state group completed, last 14 days
     Board - Bugs            layout board, type Bug, group by state
     Epic roadmap            type Epic, layout gantt
   Workspace views:
     All open bugs           across all projects the user can see
     My work                 assigned to current user, all projects
   Dynamic current-user filters must use the existing filter token mechanism;
