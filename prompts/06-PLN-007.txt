CONTEXT AND A CRITICAL NAMING CONSTRAINT
--------------------------------------------------------------------------------
The existing `type` query parameter on work item endpoints already means the
state group (all / active / backlog). It is used by the active and backlog
views. Do NOT repurpose it.

New parameters:
  type_id=<uuid>            single type
  type_id__in=<uuid,uuid>   multiple types
  group_by=type_id
  sub_group_by=type_id
  order_by=type__name

Frontend filter keys: `type_id` (array of UUIDs). Display property key:
`issue_type` (already referenced in
apps/web/core/components/issues/issue-layouts/list/block.tsx:236).

Before coding, grep for `issue_type` in
apps/web/core/store/issue/helpers/issue-filter-helper.store.ts and
apps/web/core/store/issue/issue-details/sub_issues_filter.store.ts - a partial
key exists. Extend it, do not create a second parallel key.

BACKEND
--------------------------------------------------------------------------------
1. Filtering
   Files:
     apps/api/plane/utils/filters/filterset.py
     apps/api/plane/utils/issue_filters.py
     apps/api/plane/app/views/issue/base.py (list, v2 list)
     apps/api/plane/api/views/issue.py (v1 list)

   Add to the issue filterset:
     type_id      exact UUID, validates the type belongs to the workspace
     type_id__in  list of UUIDs, max 20
   Behaviour:
     - Invalid UUID -> 400 with a field error, not 500.
     - Type from another workspace -> 400 or empty result; choose empty result
       and do not leak existence.
     - Combine with state, assignee, priority, label, cycle, module, date
       filters using AND.
     - If the project has types disabled, ignore the filter and return the
       legacy result with a header `X-Plane-Types-Disabled: true`.
     - Keep `type` (state group) untouched.

2. Grouping
   File: apps/api/plane/utils/grouper.py
   - Add `type_id` grouping. Each group:
       {"key": "<uuid>", "name": "Bug", "type_id": "...", "count": n,
        "items": [...]}
   - Sub-group by type plus state is allowed.
   - Unknown/null type groups under key "none" with name "No type" (only for
     projects with types disabled; enabled projects must have a type).
   - Preserve existing group shapes for state/priority/etc.

3. Ordering
   File: apps/api/plane/utils/order_queryset.py
   - order_by=type__name and -type__name.
   - NULL types last.

4. Projections
   Every list/detail serializer must include type without an extra query:
     type_id, type: {id, key, name, logo_props, is_epic}
   Files:
     apps/api/plane/app/serializers/issue.py
     apps/api/plane/api/serializers/issue.py
     apps/api/plane/app/serializers/draft.py
     any list projection in app/views/issue
   Add select_related("type") to list/detail querysets. Assert query count in
   tests: 50 items, constant queries.

5. Analytics
   Add a type breakdown to the existing analytics endpoints:
     GET /api/workspaces/<slug>/projects/<pid>/analytics/?type=work-items
   Add `group_by=type_id` support and a `type` dimension in the response.
   Do not break the existing state/priority dimensions.

6. Saved Views
   Views store filters/display as JSON, so no schema change is needed if the
   serializer passes unknown keys through. Verify:
     apps/api/plane/app/serializers/view.py
     apps/api/plane/app/views/view/base.py
   - Accept type_id in filters and issue_type in display_properties.
   - Validate the shape on write; reject unknown keys only if the current code
     already does.
   - A view saved with a type filter must reproduce the same list after reload
     and for another project member.

7. Seed standard Views (management command, idempotent):
   `python manage.py seed_standard_views --workspace workspace-test`
   Creates, for SDLC:
     My open bugs        type Bug, state group unstarted+started, assignee=me
     Ready for testing   type Bug, state In Testing
     Reopened            type Bug, state Reopened
     Sprint scope        current cycle, all types
   Sets is_public=true (shared) and a stable name; re-running updates filters
   instead of duplicating. "My open bugs" uses a dynamic "current user" token if
   the view model supports it; otherwise create it per user on first open.
